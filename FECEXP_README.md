## 3. Уточнения аудита по фактическому коду (важно для статьи)

1. **CC в апстриме не подключён к транспорту**: `internal/quic_config.go:23` отбрасывает `cfg.CongestionControl`; публичный API quic-go v0.40 не даёт выбора CC — транспорт всегда на встроенном CUBIC. «BBRv3» инструмента (`internal/congestion/`, `--cc=bbrv3`) — их собственный слой метрик/моделирования через tracer, НЕ транспортный CC. Следствие: стенд DOE фактические CC-руки = CUBIC; BBR-класс покрыт аналитикой и симуляцией; перенос на BBR-стек — дальнейшая работа.
2. **Лимит датаграмм**: `MaxDatagramFrameSize=1200` (hardcoded в quic-go v0.40), минус varint-заголовок кадра → payload символа = 24+1173. В стрим-режиме лимита нет. Зафиксировано как параметр стенда.
3. **Пакеты QUIC-рукопожатия паддированы до ~1200 Б** — без `ResetGroupCounter()` сдвигали фазу group-aligned-паттерна (найдено отладкой; закрыто синхронизацией с границами групп).
4. CC-сигналы для контроллера доступны через `logging.ConnectionTracer` (`LostPacket`, `UpdatedMetrics` с RTTStats/cwnd/in-flight) — что и использует adaptive.go.
5. Правило RFC 9265 на датаграммном пути соблюдается автоматически и неустранимо: пакет, переносивший датаграмму, потерян на транспортном уровне независимо от восстановления данных — CC видит сырую потерю (случай A). «FEC-прозрачный» CC (случай B) на стоковом quic-go невозможен — остаётся теоретической границей аналитической модели.

## 4. Сценарий использования

```
# сервер
fecexp server --listen 0.0.0.0:7911
# клиент (пример: адаптивный RS, Гилберт 5%/L=3, датаграммы)
fecexp client --addr SERVER:7911 --mode datagram --fec adaptive --k 20 --r 2 \
  --pps 400 --duration 60s --loss-model gilbert --loss-p 0.05 --loss-burst 3 --seed 1
# каузальная валидация
fecexp selftest
```

Вывод — JSON-строки с префиксом `RESULT ` (клиент: отправка/инжекция/RTT; сервер: доставка/восстановление/OWD).

## 5. Ограничения (честно)

- Символ 1173 Б (не 1200) — следствие лимита DATAGRAM-кадра; сравнение режимов ведётся при одинаковом размере символа.
- Инжектор действует только на исходящий трафик клиента (прямое направление); ACK не теряются.
- Сервер не инжектирует потери (обратный канал чист) — зафиксировано в дизайне DOE.
- Адаптивный контроллер — Case A (RFC 9265), lookup-политика без инлайн-вычисления DP Гилберта (таблица покрывает сетку (p̄, L)).
